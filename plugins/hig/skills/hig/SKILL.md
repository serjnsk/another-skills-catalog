# /hig — дизайн по Apple Human Interface Guidelines

Цель: когда ты рисуешь экран приложения, не угадывай размеры и цвета — бери их из HIG.
Все числа ниже и в `references/` взяты с developer.apple.com/design/human-interface-guidelines
(актуальная версия — эпоха Liquid Glass, 2025–2026). Значения, которых в тексте HIG нет, помечены «вне HIG».

Правила из HIG написаны для платформ Apple, но их базовые числа (размер касания, шкала шрифтов,
контраст) делают удобнее любой мобильный интерфейс — применяй их и к Android/веб-макетам, если
пользователь не просит другую систему (Material и т.п.).

## Режимы

- **Проектирование** (по умолчанию, в т.ч. автоматически): соблюдай «Ядро» ниже, для каждого
  используемого компонента открой нужный раздел `references/components.md`, в конце пройди чек-лист.
- **`/hig audit <файл>`**: прочитай макет, пройди чек-лист по каждому экрану, проверь пары цветов
  через `scripts/contrast.py`, выдай список нарушений: *что* → *правило HIG с числом* → *как исправить*.
  Исправляй сам, только если пользователь попросил.
- **`/hig <тема>`**: кратко ответь по теме из references; если там не хватает — `scripts/fetch_hig.py <slug>`.

## Ядро — всегда

### Касание и расстояния
- Контрол по умолчанию **44×44 pt**, абсолютный минимум **28×28 pt** (iOS/iPadOS/watchOS). Видимая часть может быть меньше, зона нажатия — нет.
- Вокруг элемента с подложкой (bezel) ~**12 pt** свободного места, вокруг элемента без подложки ~**24 pt** от видимых краёв.
- Другие платформы: macOS 28/20, tvOS 66/56, visionOS 60/28 pt (по умолчанию/минимум); в visionOS центры кнопок не ближе **60 pt**.

### Текст
- iOS: основной текст **17 pt** (Body), минимум **11 pt**. Шкала по умолчанию (размер/интерлиньяж, pt):
  Large Title 34/41 · Title 1 28/34 · Title 2 22/28 · Title 3 20/25 · Headline 17/22 Semibold · Body 17/22 ·
  Callout 16/21 · Subhead 15/20 · Footnote 13/18 · Caption 1 12/16 · Caption 2 11/13.
- Используй эти стили, а не произвольные кегли; иерархия — весом, размером, цветом. Не более 1–2 гарнитур.
- Не используй Ultralight/Thin/Light в интерфейсе. Трекинг SF Pro зависит от кегля (17 pt → −0.026 em) — таблица в `references/typography.md`.
- Вёрстка должна выдерживать увеличение текста до **200 %** (AX-размеры): строки переносятся, ряды становятся столбцами, текст не обрезается.

### Цвет и контраст
- Контраст текста: до 17 pt — **4.5:1**, от 18 pt или жирный — **3:1**. Проверяй в светлой **и** тёмной теме. Для своих цветов (особенно мелкий текст) стремись к **7:1**.
- Стандартные системные цвета на белом в основном **не** проходят 4.5:1 (Blue #0088FF = 3.5:1) — для мелкого цветного текста бери Increased-contrast варианты (`--blue-text` #1E6EF4 и др.), см. `references/color.md`.
- Любой свой цвет — в 4 вариантах: светлый, тёмный, и оба с повышенным контрастом. Смысл цвета единый по всему приложению.
- Никогда не кодируй смысл только цветом — добавь иконку, форму или текст.
- Liquid Glass: цвет на стекле — экономно; главное действие выделяй заливкой фона кнопки, а не цветом её иконки.

### Раскладка
- Уважай safe area (Dynamic Island, индикатор Home, бары); фон контента уводи под бары до краёв экрана.
- Раскладку выбирай по size class (compact/regular), а не по модели устройства или ориентации.
- Самое важное — сверху и в начале строки; связанное группируй; вспомогательное прячь (progressive disclosure).
- Контролы отделяй от контента материалом Liquid Glass и scroll edge effect, а не плотной подложкой.
- Вне HIG (стандарт UIKit): поля по краям **16 pt** на iPhone (compact width), **20 pt** на regular width.

### Компоненты — самые частые лимиты (подробно в `references/components.md`)
- Выделенных (prominent) кнопок на экране — **1–2**; в toolbar одно главное действие, справа.
- Toolbar: не больше **3** групп элементов, заголовок короче **15** символов.
- Tab bar в iOS плавает внизу (Liquid Glass), на iPad — сверху; для настраиваемых вкладок по умолчанию **≤ 5**. Вкладки — для навигации, не для действий.
- Алерт: заголовок до **2** строк, до **3** кнопок, подписи в **1–2** слова. Шит: detent medium ≈ **половина** large; одновременно только **1** шит.
- Segmented control: **≤ 5** сегментов на iPhone (**5–7** на широком экране). Sidebar: **≤ 2** уровня иерархии.
- Подменю — **1** уровень вложенности; контекстное меню — до **~3** групп; pull-down — от **3** пунктов.

### Движение и доступность
- Уважай Reduce Motion: вместо сдвигов/зума — затухания, без автоповторяющихся анимаций.
- Не автозапускай аудио/видео без кнопок управления; не делай элементов, исчезающих по таймеру.
- У каждого жеста — альтернатива кнопкой. Иконки-кнопки — с текстовой подписью для VoiceOver.

## HTML-прототипы

Подключай токены: скопируй `assets/hig-tokens.css` рядом с прототипом (или вставь в `<style>`).
Там: системный шрифтовой стек SF, классы стилей `.large-title … .caption2` (с трекингом, `.em` — emphasized),
системные и семантические цвета со светлой/тёмной темой (`data-theme` для принудительной),
`--tap: 44px`, отступы, safe-area через `env()`. Ставь `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">`.

## Скрипты

- `python3 scripts/contrast.py "<цвет текста>" "<фон>" [--size 15] [--bold]` — WCAG-контраст и вердикт по порогам HIG (понимает `rgba()` с альфой).
- `python3 scripts/fetch_hig.py <slug> [slug…]` — живая страница HIG в Markdown (slug из URL, например `tab-bars`, `sheets`); `--list` — все страницы; `--grep "<regex>"` — поиск по всем ~170 страницам. Используй, когда справочника не хватает или нужно свериться с первоисточником.

## Чек-лист перед сдачей экрана

1. Все интерактивные зоны ≥ 44×44 pt (крайний случай ≥ 28×28); между ними есть отступ 12/24 pt.
2. Текст только из шкалы стилей; ничего мельче 11 pt; нет Light/Thin.
3. Все пары текст/фон ≥ 4.5:1 (≥ 3:1 для 18 pt+/жирного) — в обеих темах; прогнан `contrast.py`.
4. Есть тёмная тема (не просто инверсия); цвета смысловые и единообразные.
5. Информация не держится только на цвете.
6. Safe area соблюдена; ничего важного под Dynamic Island и индикатором Home.
7. Компоненты использованы по назначению и с числами из `components.md` (кол-во вкладок, кнопки в алерте, высоты и т.д.).
8. Макет переживёт текст ×2: переносы вместо обрезаний, столбцы вместо рядов.
9. Главное действие одно и заметно; деструктивные действия — красным и с подтверждением.
10. Тексты кнопок — глаголы, коротко, в едином тоне (см. раздел Writing в `patterns.md`).
