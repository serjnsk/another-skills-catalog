## 1. Платформа: iPhone vs iPad

| Характеристика | iPhone (iOS) | iPad (iPadOS) |
|---|---|---|
| Дисплей | средний, высокого разрешения | большой, высокого разрешения |
| Дистанция просмотра | не больше **1–2 футов** | обычно в пределах **~3 футов** |
| Хват | одна или две руки, смена portrait/landscape | в руках, на столе, на подставке |
| Ввод | Multi-Touch, виртуальная клавиатура, голос; гироскоп/акселерометр, spatial-взаимодействия | Multi-Touch, виртуальная и внешняя клавиатура, трекпад/мышь, Apple Pencil, голос — часто комбинируются |
| Сессии | от минуты-двух до часа+; частое переключение между приложениями | от пары быстрых действий до многочасовой работы; несколько приложений на экране, drag and drop |
| Системные фичи | Widgets, Home Screen quick actions, Spotlight, Shortcuts, Activity views | Multitasking, Widgets, Drag and drop |

**iPhone — делай:**
- Держи на экране минимум контролов; второстепенное — доступно в одно-два касания (progressive disclosure).
- Бесшовно подстраивайся под ориентацию, Dark Mode и Dynamic Type.
- Размещай важные контролы в средней и нижней части экрана — туда проще дотянуться; поддерживай swipe для «назад» и для действий в строках списка.
- С разрешения пользователя используй данные платформы вместо ручного ввода (платежи, биометрия, геолокация).

**iPad — делай:**
- Используй большой экран, чтобы выдвинуть контент вперёд; минимум модальных экранов и full-screen переходов; контролы — в зоне досягаемости, но не поверх контента.
- Размер и плотность контента выбирай исходя из дистанции просмотра и способа ввода.
- Поддерживай жесты, физическую клавиатуру/трекпад и Apple Pencil, в том числе в комбинации.
- Адаптируйся к ориентации, режимам multitasking, Dark Mode, Dynamic Type и к запуску на macOS.

## 2. Layout

### 2.1 Визуальная иерархия
- **Порядок по важности:** читают сверху вниз и от leading к trailing — главное ставь вверху и у leading-края. Для RTL-языков предпочитай системные компоненты, которые сами зеркалят раскладку.
- **Выравнивание и отступ = иерархия.** Выровненные элементы воспринимаются как связанные, сдвинутые вправо (indent) — как подчинённые предыдущему.
- **Группируй связанное** негативным пространством, контейнерами или разделителями.
- **Progressive disclosure:** disclosure-треугольники, меню, вложенные экраны, прокручиваемые секции — чтобы не вываливать всё сразу (особенно в медиа-приложениях).
- **Отделяй контролы от контента:** контролы — на Liquid Glass. НЕ подкладывай под контролы сплошной или полупрозрачный цветной фон — вместо этого используй **scroll edge effect**, который приподнимает контролы над контентом.
- Полноэкранный фон протягивай **под** sidebar, toolbar и tab bar до краёв экрана/окна.
- Если sidebar/inspector закрывает важную часть фоновой картинки — применяй **background extension effect** (картинка отражается и размывается под соседним компонентом, создавая иллюзию продолжения).

### 2.2 Адаптивность
Интерфейс обязан переживать:
- regular/compact **size classes** по горизонтали и вертикали;
- разные размеры экранов, ориентации и соотношения сторон;
- системные элементы вроде **Dynamic Island**;
- внешние дисплеи, Display Zoom, изменяемые окна на iPad и Mac;
- изменение размера текста;
- локализацию: LTR/RTL, форматы даты/времени/чисел, варианты шрифтов, длина строк.

Правила:
- Уважай системные **safe areas, margins и layout guides**; раскладка должна оставаться узнаваемой при повороте, ресайзе окна, подключении дисплея, смене устройства.
- Даже если приложение зафиксировано в одной ориентации (например, landscape-игра) — интерфейс всё равно должен нормально ресайзиться.
- **Готовься к Dynamic Type:** соседние по горизонтали view могут перестраиваться в вертикальный стек; строки таблиц и контейнеры растут по высоте, чтобы текст не обрезался и не наезжал; однострочная строка может стать многострочной.
- Тестируй сначала **самый большой и самый маленький** layout, с разными size classes, локализациями и размерами текста (симулятор в Device Hub, iPhone Mirroring на Mac, ресайз на iPad).
- Фоновую графику при смене пропорций экрана **масштабируй до заполнения**, не меняя её aspect ratio; учитывай, что окно может быть очень широким и низким или узким и высоким — арт должен выходить за «стандартную» видимую область.

### 2.3 Size classes (iOS, iPadOS)
- Каждое измерение — **compact** или **regular**. Горизонтальный класс: узко (compact) / широко (regular). Вертикальный: низко (compact) / высоко (regular).
- Класс задаёт система по типу устройства, конфигурации окон и multitasking (full screen, Slide Over, iPhone Mirroring на Mac). Возможны **все 4 комбинации**.
- **Решения по раскладке — по size class, а не по типу устройства (idiom) или ориентации:** они не говорят, сколько места реально доступно.
- Продумай все комбинации: landscape-раскладка iPhone (regular width + compact height) не использует вертикаль iPad в landscape при regular height; раскладка только под compact portrait оставит пустоту при regular width на iPad.
- **Функциональность не меняется** при смене size class — меняется только, сколько её видно. На большом пространстве можно заменить **tab bar → sidebar** или вынести пункты из overflow-меню.
- Idiom при ресайзе остаётся прежним — раскладка должна выглядеть «родной» для платформы.

### 2.4 Layout guides и safe area
- **Layout guide** — прямоугольная область для позиционирования/выравнивания; системные guides дают стандартные поля вокруг контента и ограничивают ширину текста для удобного чтения. Можно создавать свои.
- **Safe area** — часть окна, не перекрытая аппаратными элементами или другими view (toolbar, tab bar, status bar). Соблюдать обязательно, чтобы Dynamic Island и системный UI не закрывали контент и контролы.

### 2.5 Другие платформы — сравнение
| Платформа | Правило / число |
|---|---|
| macOS | не ставь контролы и важное внизу окна (окно часто уезжает за нижний край экрана); не выводи контент за корпусом камеры у верхнего края |
| tvOS | safe area: отступ основного контента **60 pt** сверху/снизу и **80 pt** по бокам; фокусируемые элементы увеличиваются — оставляй между ними запас |
| visionOS | поддерживай ресайз окон/volumes; при очень больших размерах центрируй контент по горизонтали; min/max размер — не для запрета ресайза; 3D в окнах — редко и с отступом внутрь; доп. контент — в соседнем окне, а не в ornament; центры кнопок не ближе **60 pt** друг к другу |
| watchOS | в ряд не больше **3** кнопок с глифами или **2** текстовых; поддерживай autorotation для контента, который показывают другим (фото, QR) |

**tvOS — сетки** (горизонтальный зазор всегда **40 pt**, минимальный вертикальный — **100 pt**):

| Колонок | 2 | 3 | 4 | 5 | 6 | 7 | 8 | 9 |
|---|---|---|---|---|---|---|---|---|
| Ширина элемента без фокуса, pt | **860** | **560** | **410** | **320** | **260** | **217** | **184** | **160** |

tvOS: у строк с заголовком — дополнительный вертикальный зазор (до центра заголовка и от заголовка до элементов); отступы строго одинаковые; частично скрытый за краем контент — одинаковой ширины слева и справа.

## 3. Status bar
(iOS/iPadOS; в macOS, tvOS, visionOS, watchOS отсутствует)
- Фон status bar по умолчанию **прозрачный** — следи за читаемостью и не создавай впечатление, что контент под ним кликабелен. Предпочтительно — **scroll edge effect** (размытый слой за status bar).
- Для полноэкранного медиа статус-бар можно **временно** скрыть (как в Photos).
- **Не скрывай навсегда**: верни его простым очевидным жестом (в Photos — одиночный тап).

## 4. Materials и Liquid Glass

Два типа материалов: **Liquid Glass** (функциональный слой контролов и навигации) и **standard materials** (различение внутри слоя контента).

### 4.1 Liquid Glass
- Отдельный функциональный слой для контролов и навигации (tab bars, sidebars и т. п.), **плавающий над контентом**; контент прокручивается и просвечивает под ним.
- **НЕ используй Liquid Glass в слое контента** (для фонов приложения — standard materials). Исключение: контролы в контенте с транзиентным интерактивным элементом (**Sliders, Toggles**) — при активации элемент на мгновение принимает вид Liquid Glass.
- **Дозируй:** системные компоненты получают Liquid Glass автоматически; на кастомных контролах — только для самых важных функциональных элементов.
- Два варианта:

| Вариант | Свойства | Когда |
|---|---|---|
| **regular** | размывает и корректирует яркость фона ради читаемости; используется большинством системных компонентов | фон может мешать читаемости; много текста — alerts, sidebars, popovers |
| **clear** | сильно прозрачный, фон остаётся заметным | только над визуально насыщенным фоном: фото, видео, медиа |

- Для **clear** над **светлым** контентом добавляй тёмный dimming-слой **35% opacity**. Над тёмным контентом или со стандартными AVKit-контролами (у них свой затемняющий слой) — не нужно.
- Внешний вид обоих вариантов меняется от системных настроек (предпочтительный вид Liquid Glass, Reduce Transparency, Increase Contrast).
- Scroll edge effect дополнительно размывает и снижает непрозрачность фона под контролами.

### 4.2 Standard materials
- Выбирай материал/эффект по **смыслу и назначению**, а не по «цвету», который он даёт — системные настройки меняют его вид.
- Поверх материалов — только **vibrant colors** (системные), иначе цвет может стать слишком тёмным/ярким/низкоконтрастным (пример ошибки: символ цвета `systemGray3` на материале почти не виден).
- **Толще** (более непрозрачный) — лучше контраст для текста и тонких деталей; **тоньше** (прозрачнее) — лучше сохраняет контекст фона.

**iOS/iPadOS — 4 толщины standard material** (для слоя контента): **ultraThin**, **thin**, **regular** (по умолчанию), **thick**.

Vibrancy-уровни (iOS/iPadOS), от большего контраста к меньшему:

| Для чего | Уровни | Ограничение |
|---|---|---|
| Labels | `label` (default), `secondaryLabel`, `tertiaryLabel`, `quaternaryLabel` | **quaternary не использовать на thin и ultraThin** — слишком низкий контраст |
| Fills | `fill` (default), `secondaryFill`, `tertiaryFill` | на любых материалах |
| Separator | один уровень `separator` | на любых материалах |

### 4.3 Материалы на других платформах
| Платформа | Правила |
|---|---|
| macOS | несколько материалов с назначением; режимы смешивания фона: behind window / within window; vibrancy в кастомных view — по тестам |
| tvOS | Liquid Glass в навигации, Top Shelf, Control Center; image views и кнопки становятся Liquid Glass при фокусе. Standard: **ultraThin** — full-screen со светлой схемой; **thin** — оверлей, частично перекрывающий контент, светлая схема; **regular** — оверлей; **thick** — оверлей, тёмная схема |
| visionOS | окна — неизменяемый системный материал **glass**; отдельного Dark Mode нет, glass адаптируется к яркости окружения; предпочитай прозрачность непрозрачным заливкам. **thin** — привлечь внимание к интерактивному (кнопки, выделение); **regular** — разделить секции (sidebar, grouped table); **thick** — тёмный элемент поверх regular-фона. Vibrancy: `label` — обычный текст, `secondaryLabel` — сноски/подзаголовки, `tertiaryLabel` — неактивное, где не нужна высокая читаемость |
| watchOS | материалы дают контекст в full-screen модальных экранах; не убирай стандартный материал модальных sheets |

## 5. Dark Mode
- Пользователь ждёт, что приложение следует системной настройке. **Не делай собственный переключатель темы** внутри приложения.
- Приложение должно хорошо выглядеть в обоих режимах, включая **Auto** (переключение по времени суток, возможно прямо во время работы приложения).
- Тестируй читаемость в Dark Mode с **Increase Contrast** и **Reduce Transparency** — по отдельности и вместе (тёмный текст на тёмном фоне может стать нечитаемым).
- Только тёмный интерфейс — **редкое исключение**, например для иммерсивного просмотра медиа (Stocks).
- Палитра Dark Mode: фоны **тусклее**, передний план **ярче**; это не простая инверсия светлых цветов.
- Используй **семантические / адаптивные цвета** (например, `separator` в iOS/iPadOS); свои цвета — через Color Set со светлым и тёмным вариантом. Никаких захардкоженных неадаптивных значений.
- **Контраст: минимум 4.5:1**; для кастомных цветов переднего плана/фона стремись к **7:1**, особенно для мелкого текста.
- Картинки контента с белым фоном — слегка **притемняй**, чтобы они не «светились» в тёмном окружении.
- **Иконки и изображения:** по возможности SF Symbols (адаптируются сами при динамических цветах или vibrancy). При необходимости рисуй отдельные интерфейсные иконки для светлой и тёмной темы (пример: тонкий контур у иконки луны на светлом фоне; тонкая обводка у тёмной капли на тёмном фоне). Полноцветный ассет, плохо выглядящий в одном режиме, — правь или делай два варианта в asset catalog.
- **Текст:** системные label-цвета — primary, secondary, tertiary, quaternary — адаптируются автоматически. Поля и текстовые view рисуй системными компонентами.
- **iOS/iPadOS — base и elevated фоны:** base (тусклее) — для «уходящих назад» слоёв, elevated (ярче) — для слоёв, выдвинутых вперёд (popover, модальный sheet); также разделяют приложения в multitasking и окна. Система переключает base→elevated сама — **используй системные фоновые цвета**, кастомный фон ломает это различение.
- macOS: desktop tinting (при graphite accent) — в кастомных компонентах с видимым фоном/рамкой добавляй немного прозрачности, только в нейтральном (бесцветном) состоянии.
- visionOS и watchOS Dark Mode не поддерживают.

## 6. Accessibility
Доступный интерфейс: **интуитивный** (знакомые, последовательные взаимодействия), **воспринимаемый** (информация не передаётся одним-единственным способом), **адаптивный** (учитывает системные настройки и персонализацию). Проверяй через Accessibility Inspector; поддержку можно показать в App Store через Accessibility Nutrition Labels.

### 6.1 Зрение
- **Увеличение текста — минимум до 200%** (в watchOS — **140%**): через Dynamic Type или свой UI.
- Размеры кастомного текста — не меньше рекомендованных:

| Платформа | По умолчанию | Минимум |
|---|---|---|
| **iOS, iPadOS** | **17 pt** | **11 pt** |
| macOS | 13 pt | 10 pt |
| tvOS | 29 pt | 23 pt |
| visionOS | 17 pt | 12 pt |
| watchOS | 16 pt | 12 pt |

- Тонкое начертание кастомного шрифта → делай кегль **крупнее** рекомендованного.
- **Контраст** (WCAG Level AA, на него опирается Accessibility Inspector; также упоминается APCA):

| Размер текста | Начертание | Мин. контраст |
|---|---|---|
| до **17 pt** | любое | **4.5:1** |
| **18 pt** | любое | **3:1** |
| любой | **Bold** | **3:1** |

- Если по умолчанию контраст ниже — обязателен более контрастный вариант при включённом **Increase Contrast**. Проверяй контраст и в светлой, и в тёмной теме.
- Предпочитай системные цвета — у них есть accessible-варианты (Increase Contrast, смена темы).
- **Не передавай смысл только цветом** (проблемные пары: красный–зелёный, синий–оранжевый): добавляй формы/иконки (например, ✓ в зелёном круге и ✕ в красном восьмиугольнике). По возможности давай настраивать цветовые схемы (графики, персонажи).
- Описывай интерфейс для VoiceOver (см. §7).

### 6.2 Слух
- Аудио/видео — с текстовыми альтернативами: **captions**, **subtitles**, **audio descriptions**, **transcripts**; оформление текста — настраиваемое.
- Звуковые сигналы дублируй **haptics** (в iOS/iPadOS есть Music Haptics и Audio graphs).
- Звуковые подсказки дублируй **визуальными** (особенно в играх и spatial-приложениях).

### 6.3 Моторика
**Размеры контролов:**

| Платформа | По умолчанию | Минимум |
|---|---|---|
| **iOS, iPadOS** | **44×44 pt** | **28×28 pt** |
| macOS | 28×28 pt | 20×20 pt |
| tvOS | 66×66 pt | 56×56 pt |
| visionOS | 60×60 pt | 28×28 pt |
| watchOS | 44×44 pt | 28×28 pt |

- **Отступы между контролами так же важны, как размер:** вокруг элементов **с bezel** (видимой подложкой/рамкой) — около **12 pt**; вокруг элементов **без bezel** — около **24 pt** от видимых краёв.
- Для частых действий — самые простые жесты; избегай кастомных многопальцевых и двуручных жестов.
- **У каждого жеста — экранная альтернатива** (свайп-удаление → ещё и кнопка удаления в режиме редактирования; свайп-закрытие → ещё и кнопка).
- Подписывай элементы для **Voice Control**; интегрируйся с **Siri и Shortcuts**.
- Поддерживай VoiceOver, AssistiveTouch, Full Keyboard Access, Pointer Control, Switch Control.

### 6.4 Речь / клавиатура
- Всё приложение должно управляться **только с клавиатуры** (Full Keyboard Access); не переопределяй системные шорткаты.
- Поддерживай **Switch Control**.

### 6.5 Когнитивные аспекты
- Простые, запоминаемые, единообразные взаимодействия; системные жесты лучше кастомных.
- **Минимум элементов, исчезающих по таймеру** — закрытие по явному действию.
- Игры: настраиваемая сложность (критерии прохождения, время реакции, помощь в управлении).
- **Не автозапускай** аудио/видео без контролов старт/стоп; учитывай глобальный отказ от автовоспроизведения.
- Поддерживай **Dim Flashing Lights** в видео.
- **Reduce Motion** — сокращай автоматические и повторяющиеся анимации (zoom, scale, движение на периферии):
  - жёстче пружины (меньше bounce);
  - анимация строго следует за жестом;
  - не анимируй смену глубины по оси z;
  - переходы по x/y/z заменяй **fade**;
  - не анимируй вход в blur и выход из него.
- **Assistive Access** (iOS/iPadOS): оставь ядро функций, убери второстепенное; многошаговые сценарии дроби на **один шаг — один экран**; для трудно обратимых действий (удаление файла) — **подтверждение дважды**.

### 6.6 visionOS (сравнение)
Pointer Control (рука/голова), Zoom. Комфорт: элементы в поле зрения, горизонтальные раскладки лучше вертикальных, не дёргать внимание по разным точкам подряд; медленнее и мягче анимации (особенно на периферии); аккуратно с движением камеры; не привязывай контент к голове; минимум больших и повторяющихся жестов.

## 7. VoiceOver
**Описания**
- Альтернативные подписи — **для всех ключевых элементов**; системные контролы имеют общие подписи — уточняй их под свою функцию; кастомным элементам — обязательно; держи подписи актуальными.
- Описывай **значимые изображения** — только то, что передаёт сама картинка (подпись рядом VoiceOver прочитает отдельно).
- Графики и инфографика: краткое описание смысла + доступ к интерактивным возможностям.
- **Декоративные изображения скрывай** от VoiceOver.

**Навигация**
- У каждого экрана — **уникальный краткий заголовок**; точные заголовки секций.
- Явно задавай **группировку, порядок и связи**, которые видны только визуально (картинка + её подпись = одна группа). Порядок чтения — как в языке/локали (US English: сверху вниз, слева направо).
- Сообщай VoiceOver об изменениях контента/раскладки.
- Поддерживай **rotor** (заголовки, ссылки и другие типы контента).
- visionOS: при включённом VoiceOver кастомные жесты не получают ввод рук по умолчанию (есть Direct Gesture mode).

## 8. Motion
- Системные компоненты уже анимированы и сами подстраиваются под accessibility и способ ввода (Liquid Glass сильнее откликается на прямое касание, мягче — на трекпад).
- **Движение — только с целью**; избыточная анимация отвлекает и может вызывать физический дискомфорт.
- **Движение — опционально:** не единственный канал важной информации; дублируй haptics и звуком.
- **Обратная связь реалистична и следует жесту:** что выдвинули сверху вниз — то и закрывают вверх, а не вбок.
- Анимации обратной связи — **короткие и точные**.
- В приложениях **не анимируй частые UI-взаимодействия** кастомных элементов сверх системного.
- **Анимацию можно прервать** — не заставляй ждать её окончания, особенно повторяющуюся.
- Используй анимированные SF Symbols (SF Symbols **5+**, см. §10.6).
- Игры: стабильные **30–60 fps**; хорошие дефолты под возможности устройства; настройки производительности/батареи (напр., режимы питания при подключении к зарядке).
- Длительности анимаций в HIG не заданы (кроме частоты ниже).

| Платформа | Особенности |
|---|---|
| visionOS | избегай движения на периферии зрения (если нужно — яркость как у остального контента); большие объекты — прозрачнее или ниже контраст (и окна — не слишком большие); перенос объекта — через fade out/in; не вращай виртуальный мир (вместо этого мгновенная смена направления во время быстрого fade); давай неподвижную рамку отсчёта; избегай продолжительных колебаний, особенно около **0.2 Hz** (малая амплитуда, полупрозрачность) |
| watchOS | layout/appearance-анимации имеют встроенный easing в начале и конце; отключить или настроить нельзя |

## 9. Interface icons
Interface icon (glyph) — упрощённая форма с минимумом цвета; в отличие от app icon — без текстур/теней. Формы задаются чёрным и прозрачным; система перекрашивает чёрные области.

- **Предельно простой, узнаваемый рисунок** со знакомой метафорой, прямо связанной с действием/контентом.
- **Единообразие всех иконок:** размер, детализация, толщина штриха (weight), перспектива. Визуально «лёгкие» иконки можно делать чуть крупнее для оптического баланса.
- **Weight иконки = weight соседнего текста** (если не нужна намеренная акцентуация).
- **Оптическое центрирование:** асимметричные иконки (например, «скачать» — тяжелее снизу) сдвигай, а сдвиг закладывай как padding в ассет — тогда геометрическое центрирование ассета даёт оптический центр.
- **Selected-состояние** не рисуй для иконок в стандартных toolbar, tab bar, кнопках — система делает сама.
- Инклюзивность: гендерно-нейтральные фигуры, понятные в разных культурах.
- Текст в иконке — только если это суть (форматирование текста); отдельные буквы **локализуй**; для «абзаца текста» — абстракция + зеркальная версия для RTL.
- Кастомные иконки — **вектор PDF или SVG** (масштабируются автоматически). PNG не масштабируется — нужны версии под каждое разрешение. Альтернатива — custom SF Symbol с подходящей scale.
- У кастомных иконок — **accessibility-описание** для VoiceOver.
- Не изображай железо Apple (только ассеты из Apple Design Resources или соответствующие SF Symbols).

## 10. SF Symbols
Тысячи символов, согласованных со шрифтом San Francisco и выравнивающихся с текстом любого веса и размера. Доступность символов и фич зависит от версии ОС. **Запрещено** использовать символы (и похожие изображения) в app icons, логотипах и прочем товарном использовании.

### 10.1 Rendering modes (4)
Пути символа разложены по слоям (например, `cloud.sun.rain.fill`: primary — облако, secondary — солнце, tertiary — капли).

| Mode | Как красит | Заметки |
|---|---|---|
| **Monochrome** | один цвет на все слои | пути — цветом или прозрачным вырезом в заливке |
| **Hierarchical** | один цвет, разная **opacity** по уровню слоя | пример: облако ~**100%**, солнце ~**50%**, капли ~**25%** |
| **Palette** | 2+ цвета, по цвету на слой | при 2 цветах и 3 уровнях secondary и tertiary получают один цвет |
| **Multicolor** | «собственные» цвета символа по смыслу | `leaf` — зелёный, `trash.slash` — красный (потеря данных); некоторые слои принимают другие цвета |

- С системными цветами символы сами адаптируются к accessibility, vibrancy и Dark Mode.
- Проверяй, читается ли выбранный mode в каждом контексте (размер, контраст с фоном); automatic даёт предпочтительный mode символа, но результат всё равно проверяй.

### 10.2 Gradients (SF Symbols **7+**)
Плавный линейный градиент из **одного** исходного цвета; во всех rendering modes, для системных и кастомных цветов и custom symbols; лучше смотрится на крупных размерах.

### 10.3 Variable color
- Показывает меняющуюся величину (уровень, сила сигнала): слои окрашиваются при прохождении порогов от **0 до 100%** (пример: `speaker.wave.3` — 0/1/2/3 волны; сам динамик не участвует).
- Для **изменения**, а не для глубины (глубина — Hierarchical).

### 10.4 Weights и scales
- **9 weights** — от ultralight до black, каждый соответствует весу San Francisco → точное совпадение с текстом.
- **3 scales:** small, **medium (default)**, large — относительно **cap height** шрифта. Scale меняет акцент символа рядом с текстом того же кегля, не ломая совпадение веса. Итого **27** комбинаций weight × scale.
- Пример `plus.circle` рядом с «ADD»: small — круг касается cap height и baseline; medium — чуть выходит за них; large — уже вертикаль плюса почти касается обеих линий.

### 10.5 Design variants
- **Outline** — самый частый вариант, похож на текст → toolbars, списки, рядом с текстом.
- **Fill** — больше визуального веса → **tab bar в iOS**, swipe actions, выделение accent-цветом.
- **Slash** — недоступность; **enclosed** (круг, квадрат, прямоугольник) — лучше читается на мелких размерах. Slash/enclosed комбинируются с outline/fill.
- Часто вариант выбирает сам контейнер: tab bar в iOS → fill, toolbar → outline.
- Есть варианты под письменности (латиница, арабская, иврит, хинди, тайская, китайская, японская, корейская, кириллица, деванагари, индийские системы цифр) — переключаются с языком устройства.

### 10.6 Animations
Работают на всех символах, во всех modes/weights/scales и на custom symbols; можно проигрывать один раз или бесконечно до условия, менять скорость, реверс.

| Анимация | Суть / когда |
|---|---|
| **Appear / Disappear** | постепенное появление / исчезновение |
| **Bounce** | короткий упругий скачок вверх/вниз с возвратом; по умолчанию 1 раз — «действие произошло/нужно» |
| **Scale** | изменение размера, **сохраняется** до сброса — выделение, отклик на выбор |
| **Pulse** | пульсация **opacity** помеченных слоёв — идущий процесс |
| **Variable color** | поочерёдная opacity слоёв; cumulative или iterative; autoreverse; open loop / closed loop (closed — бесшовно, как круговой прогресс) — прогресс, подключение, трансляция |
| **Replace** | смена символа: **down-up** (смена состояния), **up-up** (смена с движением вперёд), **off-up** (акцент на следующем состоянии) |
| **Magic Replace** | умный переход между родственными символами (slash, бейджи); теперь default для replace; для несвязанных — fallback down-up |
| **Wiggle** | покачивание по оси — привлечь к изменению/призыву к действию |
| **Breathe** | плавно opacity + размер — идущая активность (запись) |
| **Rotate** | вращение целиком или частей (By Layer, лопасти вентилятора) — процесс идёт |
| **Draw On / Draw Off** (SF Symbols **7+**) | прорисовка по направляющим точкам, слои разом/со сдвигом/по одному — прогресс, направление |

- Анимируй **умеренно**, каждая анимация — с ясной целью; учитывай тон бренда.

### 10.7 Custom symbols
- Начинай с экспортированного шаблона похожего символа; совпадай с системными по детализации, оптическому весу, выравниванию, позиции, перспективе. Требования: простой, узнаваемый, инклюзивный, прямо связан с действием.
- Символы, изображающие продукты/фичи Apple, **нельзя кастомизировать** (помечены Info-значком).
- Annotating: каждому слою — цвет или уровень (primary/secondary/tertiary).
- Negative side margins для оптического выравнивания (имена вида `left-margin-Regular-M`).
- Для анимаций — аннотируй слои, Z-order, группы; рисуй цельные фигуры + erase layer вместо вырезов; тестируй все пресеты.
- Enclosures и бейджи — из component library SF Symbols, не рисуй их в символе.
- Accessibility-описание обязательно; никаких копий продуктов Apple.

## 11. Images
- **Point** — абстрактная единица; в 2D point = N пикселей в зависимости от дисплея; в visionOS point — угловая величина.
- Scale factor: **@1x** = 1:1 (1 px на 1 pt), **@2x** = 2:1, **@3x** = 3:1 (круг 10×10 → 20×20 → 30×30 px).

| Платформа | Scale factors |
|---|---|
| **iOS** | **@2x и @3x** |
| **iPadOS**, watchOS | **@2x** |
| visionOS | **@2x или выше** |
| macOS, tvOS | @1x и @2x |

- Все растровые ассеты — в высоком разрешении для каждого поддерживаемого устройства; суффиксы `@1x/@2x/@3x` в имени.
- Рисуй в **минимальном разрешении** и масштабируй вверх; контрольные точки векторов — на целых значениях @1x (тогда на 2x/3x они тоже на пиксельной сетке).

| Тип изображения | Формат |
|---|---|
| Bitmap / растр | de-interlaced **PNG** |
| PNG без нужды в 24-bit цвете | **8-bit палитра** |
| Фото | **JPEG** (оптимизированный) или **HEIC** |
| Stereo / spatial фото | stereo **HEIC** |
| Плоские и интерфейсные иконки, плоский арт с масштабированием | **PDF или SVG** |

- К каждому изображению — **цветовой профиль**; тестируй на реальных устройствах (пикселизация, растяжение, сжатие).

**Другие платформы:**
| Платформа | Числа и правила |
|---|---|
| tvOS | layered image = **2–5** слоёв (parallax); для app icon обязателен, для прочих фокусируемых картинок и Top Shelf — желателен; фон — **непрозрачный** (иначе ошибка); текст — в верхнем слое; safe zone вокруг переднего плана; runtime-слои — `.lcr`; launch screen — статичный |
| visionOS | app icon — **2–3** слоя; 2D — вектор; растр выше @2x — с качественной фильтрацией, осторожно с производительностью выше **@6x**; spatial photo — stereo HEIC, текст поверх — feathered glass background; spatial-контент — в отдельном view (sheet/окно), крупно и по центру; генерация spatial scene — до нескольких секунд |
| watchOS | избегай прозрачности (кроме template-иконок); autoscaling PDF, рисуй под 40 и 42 mm @2x. Масштаб: 38 mm **90%**, 40 mm **100%**, 41 mm **106%**, 42 mm **100%**, 44 mm **110%**, 45 mm **119%**, 49 mm **119%** |

## 12. App icons
Иконка — ключ бренда: Home Screen, поиск, уведомления, Settings, share sheets.

### 12.1 Слои
- **iOS, iPadOS, macOS, watchOS:** background-слой + **один или несколько** foreground-слоёв; система добавляет свойства Liquid Glass — specular highlights, refraction, translucency (адаптируются к размеру, могут меняться между версиями ОС). Сборка и превью — в **Icon Composer** (фон, позиции слоёв, эффекты, варианты default / dark / mono, экспорт в Xcode).
- **tvOS:** **2–5** слоёв, parallax при фокусе. **visionOS:** фон + **1–2** слоя сверху, 3D-объект с тенями и тиснением по альфе. Для tvOS/visionOS — image stack в Xcode.
- Foreground — с **чёткими краями** (без мягких/растушёванных), варьируй opacity для глубины (импортируй непрозрачные слои, прозрачность настраивай в Icon Composer).
- Фон: сплошной цвет или градиент (Icon Composer поддерживает оба); импортированный фон — **full-bleed и непрозрачный**.
- Слои — вектор (SVG/PDF), текст — в кривые; mesh-градиенты и растр — **PNG** (lossless).

### 12.2 Форма
- iOS/iPadOS/macOS — квадрат, система скругляет углы концентрично с UI и корпусом; tvOS — прямоугольник со скруглением; visionOS/watchOS — квадрат с **круглой** маской.
- Отдавай **немаскированные** слои правильной формы (заранее скруглённые портят блики и дают рваные края).
- Главное — **по центру** (особенно для круглых visionOS/watchOS); используй сетки из шаблонов Apple Design Resources.

### 12.3 Дизайн
- Простота: одна суть, минимум фигур; простой фон, не обязательно заполнять всю канву.
- Одинаковый дизайн на всех платформах.
- Хорошо работают **заполненные перекрывающиеся фигуры** с прозрачностью/размытием.
- Текст — только если критичен для бренда (не доступен, не локализуется, мелкий); можно инициал; никаких «Watch», «Play», «New», «For visionOS». В tvOS текст — поверх остальных слоёв.
- **Иллюстрации вместо фото**; без очень тонких линий и острых углов; не копируй UI-компоненты и скриншоты; никаких копий железа Apple.
- **Не рисуй эффекты сам** (блики, тени между слоями, фаски, blur, glow) — система делает их динамически; если всё же добавил — тестируй. Группы слоёв в Icon Composer — для эффектов на уровне группы (specular, refraction, translucency).

### 12.4 Appearances (iOS, iPadOS, macOS)
- Варианты: **default, dark, clear light, clear dark, tinted light, tinted dark** — не предоставленные система сгенерирует сама.
- Одинаковые ключевые элементы во всех вариантах — не меняй состав.
- Dark/tinted должны смотреться рядом с системными иконками и виджетами; dark приглушённее, clear/tinted — ещё сильнее. Dark делай на базе светлой; избегай слишком ярких изображений; **цветной фон** обычно даёт лучший контраст в dark.
- Alternate app icons (iOS, iPadOS, tvOS, совместимые в visionOS) — каждая с собственными dark, clear, tinted вариантами; близки к продукту, не похожи на чужие приложения; проходят App Review.
- tvOS — safe zone (фронтальные слои обрезаются сильнее); visionOS — не рисуй «дыр»/вогнутостей в фоне; watchOS — **не чёрный** фон.

### 12.5 Спецификации
| Платформа | Форма макета | Форма после маски | Размер макета | Стиль | Appearances |
|---|---|---|---|---|---|
| **iOS, iPadOS, macOS** | квадрат | скруглённый квадрат | **1024×1024 px** | Layered | default, dark, clear light, clear dark, tinted light, tinted dark |
| tvOS | прямоугольник (landscape) | скруглённый прямоугольник | **800×480 px** | Layered (Parallax) | — |
| visionOS | квадрат | круг | **1024×1024 px** | Layered (3D) | — |
| watchOS | квадрат | круг | **1088×1088 px** | Layered | — |

- Меньшие размеры (Settings, уведомления) система генерирует сама.
- Цветовые пространства: **sRGB** (цвет), **Gray Gamma 2.2** (grayscale), **Display P3** (wide gamut — iOS, iPadOS, macOS, tvOS, watchOS).

## 13. Branding
- Голос и тон бренда — во всех текстах.
- **Accent color — дозированно:** не красить им все контролы; только главные действия и индикаторы статуса (бейдж непрочитанного, иконка выбранного таба). Бренд-цвет лучше перенести **в слой контента** — он проходит под Liquid Glass-контролами и подхватывается ими.
- Кастомный шрифт — если читаем на всех размерах и поддерживает Bold Text и Dynamic Type; удачная схема: свой шрифт для заголовков, системный — для body и подписей (см. `typography.md`).
- Бренд — через **знакомые компоненты**; при кастомизации сохраняй размеры, расположение, поведение.
- Бренд **уступает контенту**; не трать место на чисто брендовые элементы.
- Стандартные паттерны: UI на ожидаемых местах, стандартные символы, привычная навигация и модальность.
- **Логотип не повторяй** по всему приложению без необходимости.
- **Launch screen — не для бренда**; брендинг — в welcome/onboarding.
- Товарные знаки Apple — не в названии и не в изображениях.

## 14. Launching и launch screen
- **Запуск мгновенный** — ждать больше пары секунд не хотят.
- Launch screen нужен в **iOS, iPadOS, tvOS**; в macOS, visionOS, watchOS — нет.
- Splash screen (если нужен) — в начале onboarding или сразу после запуска, но это не launch screen.
- **Восстанавливай состояние**: позиция прокрутки, окна в прежнем месте и состоянии.

**Launch screen:**
- Задача одна — ощущение скорости; не онбординг, не сплэш, не место для творчества.
- **Почти идентичен первому экрану** — иначе вспышка при смене. Если сначала показывается сплошной цвет — launch screen = только этот цвет.
- Соответствует **текущей ориентации и теме** (светлая/тёмная).
- **Без текста** (не локализуется).
- **Без рекламы и логотипов**, если они не являются постоянной частью первого экрана; не похож на сплэш или окно «About».
- iOS/iPadOS: запускайся в текущей ориентации; если интерфейс только в одной — запускайся в ней; landscape-only корректно работает при повороте и влево, и вправо.
- tvOS: launch screen статичный; live-TV может сам начать воспроизведение через несколько секунд бездействия. visionOS: даже для fully immersive — старт в Shared Space с окном и кнопкой входа в Full Space.

## 15. Controls (Control Center, Lock Screen, Action button)
Здесь «control» — кнопка или тумблер приложения в системных местах (iOS, iPadOS, macOS; нет в watchOS, tvOS, visionOS).

- **Анатомия:** symbol image + title + (опционально) value. Control Center — символ, на крупных размерах ещё title и value; Lock Screen — только символ; Action button (iPhone) — при удержании символ и value в Dynamic Island.
- Предлагай действия, полезные **без запуска приложения** (например, старт Live Activity).
- Обновляй состояние после взаимодействия, завершения действия или по push.
- Символ должен сам объяснять действие; у toggle — символы для **обоих** состояний (`door.garage.open` / `door.garage.closed`).
- Анимируй смену состояний toggle; кнопка с длительным действием — анимация до завершения.
- **Tint color** под бренд — красит символ toggle во включённом состоянии и значение/символ в Dynamic Island.
- Если нужна настройка (какая лампа) — запроси при добавлении.
- Hint text для Action button — **глаголом** (например, «Hold for Silent»).
- Изменяемые title/value — задай **placeholder**.
- На заблокированном устройстве **скрывай чувствительное** (title, value, при необходимости состояние символа); действия, влияющие на безопасность (замки, машина), — только после разблокировки.
- Камера с заблокированного экрана (iOS **18+**): тот же UI камеры, что в приложении; объясни, как добавить control; всё кроме съёмки — после разблокировки.

## 17. Чек-лист для макета / HTML-прототипа
Все пункты выведены из разделов выше.

- [ ] Главное — вверху и у leading-края; связанное сгруппировано; вложенность показана отступом.
- [ ] Контролы и навигация — плавающий слой Liquid Glass над контентом; под ними **нет** сплошной/полупрозрачной цветной подложки — вместо неё scroll edge effect (размытие у края).
- [ ] Liquid Glass не используется для карточек/фонов контента; clear-вариант — только над фото/видео, над светлым медиа — dimming **35%**.
- [ ] Полноэкранный фон уходит под tab bar / toolbar / sidebar; safe area и Dynamic Island не перекрывают контент.
- [ ] Раскладка решается по size class (compact/regular), на широком iPad tab bar может стать sidebar, функции те же.
- [ ] Тач-цели **≥ 44×44 pt** (абсолютный минимум **28×28 pt**); зазор ~**12 pt** у элементов с подложкой, ~**24 pt** у элементов без неё.
- [ ] Основной текст **17 pt**, не меньше **11 pt**; раскладка выдерживает увеличение текста **до 200%** (стеки перестраиваются, строки растут).
- [ ] Контраст ≥ **4.5:1** (текст до 17 pt), ≥ **3:1** (18 pt+ или bold); для кастомных цветов стремиться к **7:1**.
- [ ] Цвет — не единственный носитель смысла (плюс иконка/форма).
- [ ] Есть светлая и тёмная тема; в тёмной — base/elevated фоны, модалки/поповеры светлее фона; белые картинки слегка притемнены; своего переключателя темы нет.
- [ ] Иконки — SF Symbols, единый weight с текстом; outline в toolbar/списках, fill в tab bar; стандартные имена символов из §9.1.
- [ ] Accent/бренд-цвет — только на главных действиях, выбранном табе, бейджах; логотип не дублируется по экранам.
- [ ] Анимации короткие, прерываемые, с fallback под Reduce Motion (fade вместо сдвигов/масштаба, без blur-анимаций).
- [ ] Каждому жесту есть кнопочная альтернатива; нет исчезающих по таймеру элементов; нет автоплея без контролов.
- [ ] Launch screen ≈ первый экран без текста и логотипа; status bar скрывается только временно (полноэкранное медиа).
- [ ] Растровые ассеты для iPhone — @2x и @3x, для iPad — @2x; иконки — SVG/PDF; фото — JPEG/HEIC.
- [ ] App icon: 1024×1024 px, квадрат без маски, слои без нарисованных бликов/теней, варианты default/dark/clear/tinted.
