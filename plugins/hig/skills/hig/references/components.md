## 0. Сквозные правила

- **Hit region кнопки/контрола — минимум 44×44 pt** (в visionOS — **60×60 pt**). Оставляй вокруг контрола воздух, чтобы его было видно и легко нажать.
- **Liquid Glass:** Tab bar, Toolbar, Sidebar плавают над контентом в слое Liquid Glass; контент просвечивает сквозь них.
- **Не крась подписи контролов в цвет, похожий на фон контента.** Если контент яркий и цветной — оставляй контролы (кнопки, tab bar, toolbar) в монохромном виде по умолчанию или бери accent color с достаточным отличием.
- **Минимум собственных фонов и тонировок у баров.** Кастомный фон спорит с системными эффектами; вид бара должен задавать слой контента, а отделение — scroll edge effect.
- **Скругления концентричны.** Стандартные кнопки, text fields, headers/footers в баре имеют радиус, концентричный углам бара; кастомный компонент тоже подгоняй концентрично.
- **Каждому кастомному контролу — press state.** Без него интерфейс кажется неотзывчивым.
- **Не полагайся только на цвет** для передачи состояния (toggles, charts): добавляй форму, заливку, галочку, паттерн.
- **Одна модальность за раз:** один sheet, один popover; ничего поверх popover, кроме alert.

## 1. Навигация

### Tab bars

Переключение между разделами верхнего уровня приложения с сохранением состояния навигации внутри каждого раздела.

- **Только навигация, не действия.** Действия над текущим экраном — в Toolbar.
- **Tab bar виден всегда** при переходах между разделами; перекрыть его может только модальное окно.
- **Число вкладок — минимально необходимое;** меньше вкладок = проще навигация. Для сложной структуры — sidebar или tab bar, превращаемый в sidebar.
- **Избегай overflow.** Если места не хватает, последняя вкладка превращается в **More** и прячет остальное в отдельный список — контент там хуже находится.
- **Не отключай и не прячь вкладки,** даже если в разделе пусто — объясни внутри, почему пусто.
- **Подписи обязательны,** по возможности **одно слово**.
- **Иконки — SF Symbols, предпочтительно filled.** В compact-размере иконка над подписью, в regular — иконка и подпись рядом.
- **Badge** (красный овал с белым числом или «!») — только для критичной информации, иначе обесценивается.
- **iOS:** tab bar **плавает над контентом у нижнего края** на фоне Liquid Glass.
  - С аксессуаром (например, MiniPlayer в Music) tab bar можно **минимизировать при скролле вниз**, аксессуар встаёт в одну линию с ним; выход — тап по вкладке или скролл к началу.
  - На trailing-конце можно разместить **отдельную вкладку поиска** (см. Search fields).
- **iPadOS:** tab bar **у верхнего края**; фиксированный или с кнопкой превращения в sidebar (`sidebarAdaptable`). Sidebar без переключения в tab bar — через navigation split view.
  - Разреши пользователю кастомизировать вкладки; **дефолтный набор — пять или меньше**, чтобы сохранять преемственность между compact и regular.
- *Для сравнения, tvOS:* высота tab bar **68 pt**, верхний край в **46 pt** от верха экрана (изменить нельзя).
- *visionOS:* tab bar всегда вертикальный у leading-края окна, раскрывается при взгляде; нужны и символ, и короткая подпись.

### Toolbars / Navigation bar

Горизонтальный набор команд, навигации и поиска у верхнего или нижнего края экрана. В iOS навигационный toolbar называют navigation bar.

Содержит три типа контента: заголовок экрана, навигацию (Back/Forward, поиск), действия (bar items: кнопки, меню).

**Состав и перегрузка**
- **Не перегружай.** Заранее реши, какие элементы уходят в overflow при сужении.
- В iPadOS/macOS overflow-меню система добавляет сама — **не делай его вручную** и не проектируй раскладку, которая переполняется по умолчанию.
- **More menu** — только если действительно нужно; туда — наименее важные действия.
- **iOS:** места мало → в основной зоне только самое важное, остальное в More menu.
- iPadOS: можно дать пользователю кастомизировать toolbar.
- Можно временно прятать toolbar ради «режима без отвлечений», но всегда давай надёжный способ вернуть.

**Заголовок**
- Полезный заголовок у каждого экрана/окна; если избыточен — оставь пустым.
- **Не используй название приложения** как заголовок.
- **Заголовок короче 15 символов,** слово или короткая фраза.
- **iOS: large title** — при скролле переходит в стандартный, при возврате наверх снова крупный (`prefersLargeTitles`).

**Навигация**
- **Стандартные Back и Close** — системными символами, **без текста «Back»/«Close»**. Кастомная версия должна выглядеть и работать так же и применяться единообразно.

**Действия**
- Символы вместо текста; текст — только там, где символа нет (например, *Edit*).
- **Системные символы без обводок** (никаких outlined circle) — секция уже служит контейнером, hover/selection система рисует сама.
- **Стиль `.prominent` — для ключевого действия** (Done, Submit): тонирует и отделяет его. **Только одно primary action, на trailing-стороне.**

**Группировка (три зоны: leading, center, trailing)**
- **Leading:** Back, показ/скрытие sidebar, затем заголовок и опционально document menu (Duplicate, Rename, Move, Export). Не кастомизируется.
- **Center:** частые полезные контролы (и заголовок, если он не слева); в iPadOS/macOS кастомизируется и сворачивается в overflow.
- **Trailing:** важное, что должно быть всегда видно; кнопки инспекторов; опционально search field; More menu; primary action (Done). Видно при любой ширине.
- Группируй по функции и частоте; навигацию и критичные действия (Done, Close, Save) — в отдельные, визуально различимые секции.
- **Максимум три группы.**
- **Не ставь кнопку с текстом вплотную к кнопке-символу** (сольются в одну) и несколько текстовых подряд — разделяй fixed space.
- **iPadOS:** toolbar и tab bar могут делить одну горизонталь сверху.

### Sidebars

Навигация по разделам/коллекциям верхнего уровня у leading-края; требует много места.

- Сначала рассмотри **tab bar** — он оставляет больше места контенту; sidebar-вариант tab bar (`sidebarAdaptable`) покрывает редко используемые разделы. Оба варианта имеют кнопку переключения и адаптируются к повороту/ресайзу.
- Sidebar **плавает над контентом в слое Liquid Glass.** Протягивай насыщенный контент под него: горизонтальный скролл или **background extension effect** (зеркалит соседний контент, будто он продолжается под панелью).
- Дай кастомизировать состав и порядок.
- Много контента → группируй через disclosure controls.
- Иконки — SF Symbols / custom symbols, не bitmap. По умолчанию иконки в accent color; фиксированные цвета — редко и со смыслом (как жёлтый VIP в Mail).
- Позволь скрывать sidebar (в iPadOS — системный edge swipe), но **не скрывай по умолчанию.**
- **Не больше двух уровней иерархии.** Глубже — split view с промежуточным списком контента.
- При двух уровнях — краткие заголовки групп без лишних слов.
- Только sidebar без tab bar: `NavigationSplitView` / `UISplitViewController`; вне SwiftUI — appearance `.sidebar` у list layout коллекции.

### Split views

Несколько соседних панелей для одновременного показа нескольких уровней иерархии (primary → secondary → опционально tertiary).

- **Постоянно подсвечивай выбранный элемент** в каждой панели, ведущей к detail.
- Поддерживай drag and drop между панелями.
- **iOS:** только в **regular**-окружении; в compact (iPhone портрет) не используй.
- **iPadOS:** **2 вертикальные панели** (как Mail) или **3** (как Keynote). Проектируй под узкие, compact и промежуточные ширины — окна iPad свободно ресайзятся; навигация между панелями должна оставаться логичной.
- Scroll edge effect: у каждой панели свой, **одинаковой высоты**.
- *Для сравнения:* в macOS thin divider = **1 pt**; в tvOS по умолчанию primary занимает **треть**, secondary — **две трети** (или половина на половину).

### Search fields

Редактируемое поле с иконкой Search, кнопкой Clear и placeholder для поиска по коллекции.

**Общее**
- Placeholder подсказывает, что и где можно искать.
- **Начинай поиск сразу при вводе;** показывай недавние запросы до ввода и подсказки во время.
- Сначала самые релевантные результаты; можно категоризировать.
- Фильтрация: **scope bar** (чёткие категории; по умолчанию широкий scope) и **tokens** (выбираемые/редактируемые термины-фильтры; сочетай с подсказками).

**iOS — три места для входа в поиск**
1. **Вкладка в tab bar** (на trailing-конце):
   - *Standard tab* — ведёт на landing page поиска с полем сверху; для контента, который хочется исследовать (подсказки, категории).
   - *Button appearance* — отдельная кнопка; тап сразу фокусирует поле и открывает клавиатуру; после выхода возвращает на прежнюю вкладку. Для быстрого поиска.
2. **В toolbar:**
   - *Снизу* — развёрнутым полем или кнопкой; по тапу анимируется в поле над клавиатурой. **Ставь снизу, если есть место** — так удобнее тянуться (Settings — единственный элемент; Mail, Notes — рядом с другими).
   - *Сверху* (navigation bar) — кнопкой; раскрывается над клавиатурой или вверху. **Сверху — если низ экрана занят важным контентом** или нижнего toolbar нет (пример Wallet).
3. **Inline с контентом** — когда поиск относится только к этому списку. Если сверху — **над списком**, можно закреплять в top toolbar при скролле.

**iPadOS**
- Частый паттерн — **search field на trailing-стороне toolbar** (особенно в split view).
- Фильтрация sidebar — поле **вверху sidebar**.
- Отдельная зона поиска (item в sidebar/tab bar) — для «discovery» с богатыми подсказками. Там можно сразу фокусировать поле, **кроме iPad только с виртуальной клавиатурой** — иначе клавиатура неожиданно перекроет экран.
- Учитывай ресайз окна; в compact — поиск над колонкой списка (Notes, Mail).

## 2. Контент и контейнеры

### Lists and tables

Данные строками в одну или несколько колонок; основной способ выражать иерархию и настройки.

- **Текст — в списки,** изображения и элементы разного размера — в collection.
- Разрешай редактирование/перестановку; **в iOS/iPadOS выбор элементов — только в edit mode.**
- Обратная связь при выборе: в навигационном списке строка остаётся подсвеченной; в списке опций — короткая подсветка, затем галочка.
- Короткий текст в строках; длинные элементы — только заголовки, контент в detail.
- Для узких таблиц рассмотри многоточие **в середине** строки (сохраняет начало и конец).
- Заголовки колонок — существительные, title-style, без точки.
- **Стиль:** grouped (headers, footers, дополнительные отступы между группами) и др.; разметка строк — `UIListContentConfiguration`.
- **Info button (detail disclosure button)** — только для показа доп. информации о строке, **не для навигации.** Для перехода вглубь — **disclosure indicator**.
- **Не добавляй index (алфавит справа) к таблице с trailing-контролами** (disclosure indicators) — будут мешать друг другу.

### Collections

Упорядоченный визуальный набор, идеален для изображений.

- Стандартная **строка или сетка**; не выдумывай кастомные раскладки.
- Для текста — таблица.
- Достаточные отступы вокруг изображений, чтобы эффекты фокуса/hover не перекрывались.
- Стандартные жесты: тап — выбор, touch and hold — редактирование, swipe — скролл.
- Анимируй вставку/удаление/перестановку.
- **Не меняй layout, пока человек с ним взаимодействует,** если это не ответ на явное действие.

### Scroll views

Прокрутка контента больше видимой области; сам scroll view невидим, кроме индикатора.

- Стандартные жесты и эластичное поведение индикатора.
- **Показывай, что есть ещё контент** — например, частично обрезанный элемент у края.
- **Не вкладывай scroll view в scroll view той же ориентации;** горизонтальный внутри вертикального — ок.
- Постраничный скролл: страница ≈ высота/ширина view; можно вычесть «перекрытие» (строку текста и т.п.) для сохранения контекста.
- Автоскролл — только насколько нужно (к найденному тексту, к точке ввода, к выделению).
- Зум — задай разумные min/max масштаба.
- **iOS/iPadOS:** в постраничном режиме можно показать **page control**; тогда **скрой scroll indicator той же оси.**

**Scroll edge effect** (iOS, iPadOS, macOS) — визуальное отделение плавающих элементов (toolbars) от контента под ними.
- **Предпочитай стиль automatic:** он даёт более плотное отделение для верхних toolbar с большим числом контролов, текста вне Liquid Glass-контролов и закреплённых заголовков таблиц. Стиль soft — только с тщательной проверкой читаемости; есть также hard.
- **Только когда scroll view действительно под плавающими элементами** — это не декор, не затемнение и не оверлей.
- **Один scroll edge effect на view;** в split view у панелей — одинаковой высоты.
- Кастомные бары — добавляй эффект вручную при необходимости.

### Status bars

Полоса у верхнего края: время, оператор, заряд.

- Фон status bar прозрачный — **не допускай, чтобы контент под ним мешал чтению** и казался интерактивным. **Предпочитай scroll edge effect** (размытие под status bar).
- Можно **временно скрыть** при полноэкранном медиа (как Photos).
- **Не скрывай навсегда;** возврат — простым жестом (в Photos — одиночный тап).

### Boxes

Визуальная группа связанных данных/контролов с рамкой или фоном, опционально с заголовком.

- Box заметно **меньше** содержащего view; иначе теряет смысл.
- Подгруппы внутри — отступами и выравниванием, **не вложенными boxes**.
- Заголовок — короткая фраза, sentence-style, без точки.
- **iOS/iPadOS:** по умолчанию фон — secondary и tertiary background colors.

### Image views

Показ изображения (stretch, scale, fit, pin); обычно неинтерактивен.

- Нужна интерактивность → системная кнопка с картинкой, не image view с добавленным поведением.
- Иконки интерфейса → SF Symbols / interface icons, не image view.
- Текст поверх изображения — обеспечь контраст (тень, подложка).
- Кадры анимации — одинакового размера, заранее отмасштабированные.

### Web views

Встроенный веб-контент.

- Если внутри вероятны переходы по страницам — включи back/forward и дай контролы.
- **Не строй на web view браузер** — для этого есть Safari.

### Charts

Визуализация данных; подчёркивай немного ключевой информации.

- **Marks:** bar — сравнение категорий/частей целого и суммы за период; line — изменение во времени и тренд; point — отдельные значения, выбросы, кластеры. Комбинируй (line + points), если это проясняет.
- **Оси:** fixed range, когда min/max осмыслены (заряд батареи **0%–100%**); dynamic — когда значения сильно варьируются. Для bar — нижняя граница **0**; для пульса ноль может скрыть разницу.
- **Шаг меток — привычный** (**0, 5, 10**), а не **1, 6, 11**.
- Плотность grid lines по задаче; при интерактивном просмотре — меньше линий, светлее подписи.
- Данные визуально главнее осей и подписей.
- **Compact:** максимизируй ширину plot area, сокращай подписи вертикальной оси, единицы — в заголовок.
- Заголовок/подзаголовок **резюмируют главный вывод** (как Weather).
- Интерактивность — да, но **критичная информация не должна требовать взаимодействия.** Мелкие marks → hit target на всю plot area со scrubbing.
- Изменения данных/осей анимируй и дублируй иначе (для VoiceOver и отключённой анимации).
- Выравнивай leading-край графика по соседним view; ось Y можно перенести на trailing-сторону.
- **Цвет — не единственный носитель смысла;** добавляй формы/паттерны; разделители между смежными цветными областями (stacked bar).
- Доступность: accessibility labels на важные элементы, Audio Graphs; без субъективных слов; однозначные форматы («**June 6**», а не «**6/6**»; «**60 minutes**», а не «**60m**»); видимые подписи осей скрывай от VoiceOver.

## 3. Презентация

### Sheets

Ограниченная по объёму задача, тесно связанная с текущим контекстом.

- **iOS/iPadOS:** sheet бывает **modal** и **nonmodal** (nonmodal — влияет на родительский экран без закрытия, как форматирование в Notes).
- Кнопки: **Cancel/Close** — закрыть без сохранения; **Done** — закрыть с сохранением/завершением; **Back** — предыдущий шаг (не закрывает sheet).
- **Done всегда в паре** с Cancel (или Back на следующих шагах). **Не показывай Cancel, Done и Back одновременно.**
- **iOS-раскладка:** single-view sheet — **Cancel на leading-краю** верхнего toolbar, **Done на trailing**. В многошаговых — расстановка меняется по шагам.
- **Один sheet за раз.** Если из sheet нужен другой — сначала закрой первый.
- Сложные/длинные сценарии (видео, фото, камера, многошаговое редактирование) — **full-screen modal**, не sheet.
- **Detents:** **large** — полная высота; **medium** — **примерно половина** полной. Large поддерживается автоматически; добавление medium → sheet встаёт на обе высоты; только medium → не раскрывается на всю высоту. Возможны кастомные detents.
- **iPhone: поддерживай medium** для постепенного раскрытия (как share sheet). Не нужен, если контент полезен только в полный рост (compose в Messages, Mail).
- **Grabber** (маленькая горизонтальная полоска сверху) — **обязателен у resizable sheet**; тап по нему циклически переключает detents; работает с VoiceOver.
- **Swipe вниз для закрытия** — поддерживай; при несохранённых изменениях подтверди через **action sheet**.
- **iPadOS:** предпочитай стили **page** или **form sheet** (центр экрана на затемнённом фоне).

### Popovers

Временное окно поверх контента, вызванное тапом по контролу.

- Для **небольшого** объёма информации/функций (несколько связанных задач).
- **Стрелка указывает прямо на источник;** не перекрывай источник и нужный контент.
- Close/Cancel/Done — только если добавляют ясность; обычно закрывается тапом снаружи или выбором. При множественном выборе — остаётся открытым до явного закрытия.
- **Автозакрытие nonmodal popover сохраняет работу;** отбрасывай только по явной Cancel.
- **Один popover за раз,** никаких каскадов; **поверх — ничего, кроме alert.**
- Переключение между popover'ами разных bar buttons — одним тапом.
- Размер — не больше, чем нужно; изменение размера — анимировано.
- **Не для предупреждений** — используй alert.
- **iOS/iPadOS: не показывай popover в compact** — там sheet / full-screen modal.

### Alerts

Критичная информация, требующая внимания прямо сейчас.

- **Редко.** Не для чистой информации без действия; не для частых отменяемых действий (удаление письма); **да** — для редкого необратимого деструктивного действия.
- **Не показывай alert при запуске** (нет сети → кэш/заглушка + ненавязчивая метка).
- Состав: заголовок, опциональный текст, **до трёх кнопок**; в iOS/iPadOS возможен **text field** (только если ввод нужен для решения, например пароль в secure field).
- **Заголовок:** конкретно, что произошло и почему; не «Error» и не «Error 329347 occurred»; **не длиннее двух строк.** Полное предложение — sentence case с точкой; фрагмент — title case без точки.
- Пояснительный текст — только если добавляет ценность; не объясняй кнопки.
- **Кнопки:** **1–2 слова**, глагол, описывающий результат («View All», «Reply», «Ignore»). **«OK»** — только в чисто информационных alert; избегай «Yes»/«No». Отмена всегда называется **«Cancel»**. Sentence case, без точки.
- **Расположение:** вероятная/default-кнопка — **справа (trailing) в ряду** или **сверху в стопке**; Cancel — слева в ряду или внизу стопки.
- **Destructive style** — только для деструктивного действия, которое человек **не выбирал сознательно** (при осознанном «Empty Trash» кнопка не красная).
- Есть деструктивное действие → **обязательно Cancel.** Cancel **не делай default**. Хочешь, чтобы alert читали, — без default-кнопки вовсе. Единственная default-кнопка → **Done**, не Cancel.
- Альтернативная отмена: выход на Home Screen (iOS/iPadOS); **Esc** или **Command-.** с клавиатуры.
- **iOS/iPadOS:** выбор вариантов, связанных с намеренным действием, — **action sheet, не alert**. Избегай прокручиваемых alert (короткие заголовки, сообщение только при необходимости).
- *Для сравнения, visionOS:* accessory view в alert — **макс. высота 154 pt, радиус 16 pt.**

### Action sheets

Модальный выбор вариантов, связанных с действием, которое инициировал пользователь.

- Вместо alert — когда нужны варианты для намеренного действия (отмена черновика в Mail: удалить / сохранить).
- Вместо меню — когда варианты возникают как следствие действия (меню открывают сознательно).
- Редко; **заголовок в одну строку;** сообщение — только если нужно.
- **Cancel — внизу** action sheet.
- **Destructive-кнопки — наверху** и в destructive style.
- **Не допускай прокрутки** action sheet.
- *Для сравнения, watchOS:* **не больше четырёх кнопок, включая Cancel** (т.е. ≤ **3** дополнительных); стили кнопок: Default, Destructive, Cancel.

### Activity views (share sheet)

Системный набор действий и шаринга в текущем контексте; появляется как sheet или popover в зависимости от устройства/ориентации.

- Вызывается **кнопкой Share**; не делай альтернативных путей.
- Не дублируй системные действия (Print); похожее своё — с уточняющим названием («Print Transaction»).
- Кастомное действие: символ SF Symbols или иконка, **центрированная в области около 70×70 px**.
- Название — глагол или короткая фраза, **без имени компании/продукта**.
- Исключай неприменимые системные действия; порядок системных менять нельзя (app-specific идут первыми).
- Extensions: минимум шагов; не открывай модальные окна поверх (кроме alert); длинная операция — продолжай в фоне, статус — в основном приложении; не уведомляй просто о завершении.

## 4. Меню

### Menus

Компактное раскрытие команд/опций по взаимодействию.

**Подписи**
- Глагол или глагольная фраза для действий (View, Close, Select); **title-style capitalization**; без артиклей.
- Недоступный пункт — **затемнён**; само меню остаётся доступным.
- **Многоточие (…)** — если действию нужен дополнительный ввод.

**Иконки**
- Стандартные иконки для стандартных действий (Share, Print, Search).
- Экономно и со смыслом; **в группе — иконки у всех пунктов или ни у одного.**

**Организация**
- Важное и частое — **сверху**.
- Логические группы разделяй **separator**; связанные команды держи вместе, даже если они разной важности (Paste рядом с Paste and Match Style).
- Длинное меню → раздели или вынеси в submenu (исключение — пользовательские/динамические списки вроде History).

**Submenus**
- Экономно. Повод — термин повторяется **более чем в двух** пунктах группы («Sort by …»).
- **Один уровень вложенности.** Если в submenu **больше примерно пяти пунктов** — сделай отдельное меню.
- Submenu доступен даже при недоступных вложенных пунктах; не используй отступы вместо submenu.

**Переключаемые пункты**
- Меняющаяся подпись по состоянию (Show Map ↔ Hide Map); добавь глагол, если неясно (Turn HDR On).
- Галочка — для активных атрибутов; пункт «снять всё» (Plain).

**iOS/iPadOS — три layout меню** (`preferredElementSize`)

| Layout | Верхний ряд | Подписи в ряду | Когда |
|---|---|---|---|
| Small | **4** пункта | нет, только символ | тесно связанные действия-группа (Bold, Italic, Underline, Strikethrough) |
| Medium | **3** пункта | символ над короткой подписью | **3** важных частых действия (Notes: Scan, Lock, Pin) |
| Large (по умолчанию) | — | все пункты списком | всё остальное |

### Context menus

Функции, относящиеся к конкретному элементу; вызываются touch and hold (или secondary click).

- **Только релевантные, частые команды,** не продвинутые.
- **Мало пунктов;** **не больше примерно трёх групп.**
- Поддерживай единообразно по всему приложению.
- **Каждый пункт дублируй в основном интерфейсе** (toolbar и т.п.).
- Submenu — **максимум один уровень**, с понятным заголовком.
- **Недоступные пункты скрывай, а не затемняй.**
- Частые пункты — ближе к точке вызова (меню может открыться вверх или вниз — возможно, порядок нужно развернуть).
- **Без клавиатурных сокращений** в context menu.
- **Деструктивные (Delete, Remove) — в конце,** помечены destructive (красный текст).
- Заголовок — редко, только если проясняет (например, число выбранных писем).
- **iOS/iPadOS:** для одного элемента — **либо context menu, либо edit menu, не оба.**
- Preview: графический, показывающий цель команд; clipping path по форме превью, чтобы углы не «прыгали» при анимации.
- iPadOS: context menu на пустом месте может создавать новый объект (новая папка в Files).

### Edit menus

Команды над выделенным контентом: Copy, Select, Translate, Look Up и т.д.

- **iOS:** компактная **горизонтальная** полоса по touch and hold / double-tap; chevron на trailing-краю раскрывает в context menu. **iPadOS:** при касании — горизонтальная, с клавиатуры/указателя — сразу вертикальный context menu. Проверяй оба стиля.
- Используй **системное** edit menu и системные жесты вызова.
- Показывай только применимые команды (нет выделения → нет Copy/Cut; буфер пуст → нет Paste).
- Кастомные команды — рядом с родственными системными, коротким глаголом, без перебора.
- Разрешай выделять и копировать нередактируемый текст контента (не подписи контролов).
- Поддерживай undo/redo; не дублируй функции edit menu отдельными контролами.
- Позиция по умолчанию — над или под выделением; можно сдвинуть, чтобы не перекрывать важное (форму и стрелку менять нельзя).

### Pull-down buttons

Кнопка, раскрывающая меню действий, напрямую связанных с её назначением (Add → что добавить; Sort → по чему).

- Для взаимоисключающих **не-команд** — pop-up button.
- **Не прячь все действия экрана** в один pull-down.
- **Минимум три пункта,** иначе смысла открывать нет (1–2 → обычные кнопки / toggles). Слишком много — тоже плохо.
- Заголовок меню — только если добавляет смысл.
- Деструктивный пункт — красным, с подтверждением через **action sheet (iOS)** или **popover (iPadOS)**.
- Иконка после подписи — если проясняет.
- iOS: можно вызывать меню жестом по кнопке (Safari, touch and hold по Tabs, с **iOS 14**).
- **More** (многоточие) pull-down — для второстепенного, но помни о потере discoverability.

### Pop-up buttons

Кнопка с меню **взаимоисключающих** опций; после выбора показывает текущее значение.

- Плоский список опций/состояний. Нужны действия, множественный выбор или submenu → pull-down.
- Полезный **выбор по умолчанию**.
- Предсказуемость без открытия: вводная подпись или название, описывающее эффект.
- Хорош при нехватке места; для редких вариантов — пункт **Custom**.
- **iPadOS:** в popover/модальном окне pop-up button вместо disclosure indicator для небольшого набора опций строки.

## 5. Кнопки и контролы

### Buttons

Мгновенное действие. Три атрибута: **style** (размер, цвет, форма), **content** (символ и/или текст), **role**.

- **Hit region ≥ 44×44 pt** (visionOS ≥ 60×60 pt); вокруг — достаточный зазор.
- **Кастомная кнопка всегда с press state.**
- **Prominent style** — для самого вероятного действия (фон в accent color). **Не больше одной-двух prominent-кнопок на экран.**
- Предпочтительный вариант выделяй **стилем, а не размером**; кнопки одного набора — одного размера.
- Не крась подписи в цвет, близкий к фону контента; на ярком контенте — монохромные подписи.
- Знакомые действия — знакомыми иконками (`square.and.arrow.up` = Share).
- Текст — если короткая подпись яснее иконки: несколько слов, **title case, начинай с глагола** («Add to Cart»).

**Roles**

| Role | Смысл | Вид |
|---|---|---|
| Normal | без особого значения | стандартный |
| Primary | default, самый вероятный выбор; срабатывает по Return, закрывает sheet/alert | accent color |
| Cancel | отменяет текущее действие | стандартный |
| Destructive | может уничтожить данные | system red |

- **Primary — самой вероятной кнопке.** **Никогда не давай primary role деструктивному действию,** даже если оно вероятнее всего.
- **iOS/iPadOS:** для немгновенного действия покажи **activity indicator внутри кнопки**, можно со сменой подписи («Checkout» → «Checking out…»); индикатор встаёт рядом с подписью (на leading-стороне), иконка кнопки скрывается.

*Для сравнения:*
- visionOS — размеры кнопок:

| Форма | Mini **28 pt** | Small **32 pt** | Regular **44 pt** | Large **52 pt** | Extra large **64 pt** |
|---|---|---|---|---|---|
| Circular | ✓ | ✓ | ✓ | ✓ | ✓ |
| Capsule (только текст) | — | ✓ | ✓ | ✓ | — |
| Capsule (текст + иконка) | — | — | ✓ | ✓ | — |
| Rounded rectangle | — | ✓ | ✓ | ✓ | — |

  Центры кнопок — **не ближе 60 pt**; кнопки **≥ 60 pt** — плюс **4 pt** отступа вокруг. Белый фон + чёрный текст зарезервирован под toggled-состояние. Rounded rectangle — в вертикальной стопке, capsule — в горизонтальном ряду.
- macOS image button — около **10 px** отступа от картинки до края; help button — **не больше одного** на окно.
- watchOS: основные действия — кнопки на всю ширину; две кнопки в ряд — одинаковой высоты.

### Toggles

Выбор между двумя противоположными состояниями (вкл/выкл).

- Только для управления состоянием; выбор из списка → pop-up button и т.п.
- Ясно, что именно переключается; разница состояний очевидна **не только цветом** (заливка, фон, галочка/точка).
- **iOS/iPadOS:**
  - **Switch — только в строке списка;** подпись не нужна, контекст даёт строка.
  - Цвет switch по умолчанию — **зелёный**; меняй (например, на accent) только при необходимости и с достаточным контрастом к выключенному виду.
  - **Вне списка — кнопка, работающая как toggle** (иконка + смена фона, как фильтр в Phone с синей подсветкой), не switch; без поясняющей подписи.
- *Для сравнения, macOS:* radio buttons обычно группами **от двух до пяти**; **больше примерно пяти** опций → pop-up button; checkbox имеет состояния on / off / mixed.

### Segmented controls

Линейный набор из **двух и более** сегментов, каждый работает как кнопка.

- Для тесно связанных вариантов, влияющих на объект/состояние/вид; сохраняет группировку и показывает выбор.
- **Не смешивай** сегменты-действия и сегменты-выбор в одном контроле.
- **Число сегментов: не больше примерно 5–7 на широком интерфейсе и не больше примерно 5 на iPhone.**
- Сегменты **одинаковой ширины**, контент схожего размера.
- **Либо текст, либо изображения** — не вперемешку.
- Подписи — существительные, title-style; вводный текст не нужен.
- **iOS/iPadOS:** для переключения между связанными subview (New Event ↔ Reminder в Calendar). Для совершенно разных разделов — **tab bar**.

### Sliders

Горизонтальный трек с thumb между min и max; участок до thumb заливается цветом.

- Можно кастомизировать трек, thumb, tint, иконки min/max по краям (маленькая / большая картинка).
- **Направление:** min — на leading, max — на trailing (вертикальный: min снизу, max сверху). Проценты — от **0** до **100**.
- Широкий диапазон → добавь **text field** (точное значение) и **stepper** (шаг на целое).
- **iOS/iPadOS: не используй slider для громкости** — используй системный volume view.
- *Для сравнения, macOS:* круговой slider — для повторяющихся значений (поворот **0–360°**; **4** полных оборота = **1440°**); linear — для фиксированного диапазона (прозрачность **0–100%**). visionOS: предпочитай горизонтальные.

### Steppers

Двухсегментный контрол (+/−) для пошагового изменения; сам значение не показывает.

- Ставь рядом с полем, показывающим значение; ясно, какое значение меняется.
- Для мелких изменений; при больших скачках — в паре с text field (число копий при печати).
- *Для сравнения, macOS:* Shift-click — шаг больше дефолтного (например, **в 10 раз**).

### Pickers

Один или несколько прокручиваемых списков значений.

- Для **средних и длинных** списков; короткий → pull-down button; очень большой → list/table (можно с index).
- Значения **предсказуемые и упорядоченные** (страны по алфавиту).
- Показывай в контексте — под редактируемым полем, внизу окна или в popover; **не переключай экран** ради picker.
- **Минуты:** по умолчанию **60** значений (**0–59**); интервал можно увеличить, если он делит **60** нацело — например, четверти часа (**0, 15, 30, 45**).
- Значения и их порядок зависят от языка/региона устройства.

**Date picker (iOS/iPadOS) — 4 стиля**
- **Compact** — кнопка со значением в accent color, открывает модальный календарь/время; **для тесного пространства**. Подтверждение — тап вне окна.
- **Inline** — только время: кнопка с колёсами; дата+время: встроенный календарь.
- **Wheels** — колёса, поддерживают ввод с клавиатуры.
- **Automatic** — выбирает система.

**Date picker — 4 режима**
- Date — месяц, день, год.
- Time — часы, минуты, опционально AM/PM.
- Date and time — дата, часы, минуты, опционально AM/PM.
- Countdown timer — часы и минуты, **максимум 23 ч 59 мин**; недоступен в стилях inline и compact.

### Page controls

Ряд индикаторов (точек) страниц плоского упорядоченного списка; текущая — закрашена.

- Только для **последовательных** страниц, не для иерархии (для сложной навигации — sidebar/split view).
- **По центру внизу** экрана/view.
- **Больше примерно 10 точек** трудно сосчитать; **больше 10** страниц-равноправных → сетка или иная раскладка.
- Точки равноудалены; при нехватке места обрезаются, а в iOS/iPadOS крайние **уменьшаются** (в примере из **9** точек: центральные **5** — обычного размера, **2-я и 8-я** — около **половины**, **1-я и 9-я** — около **четверти**).
- Кастомные индикаторы: простые (без negative space, текста, внутренних линий), например `location.fill` для текущей локации в Weather. **Не больше двух разных изображений** индикаторов. **Не раскрашивай** индикаторы.
- Взаимодействие: **тап** слева/справа от текущей точки — предыдущая/следующая; **scrubbing** (провести пальцем) — последовательно, за край — к первой/последней. **Не анимируй переходы при scrubbing** — только при тапе.
- **Фон (3 стиля):**
  - **Automatic** — фон только при взаимодействии; когда page control не главный навигатор.
  - **Prominent** — фон всегда; только если это главный навигационный контрол экрана.
  - **Minimal** — фона нет; **без scrubbing** (нет обратной связи).
- В паре со scroll view — скрывай scroll indicator той же оси.

### Disclosure controls

Показ/скрытие деталей, связанных с контролом или view.

- Частое — всегда видно наверху, продвинутое — скрыто по умолчанию.
- **Disclosure triangle:** смотрит внутрь от leading-края, когда скрыто, и вниз, когда раскрыто; подпись описывает скрытое («Advanced Options»).
- **Disclosure button:** вниз — скрыто, вверх — раскрыто; ставь рядом с контентом; **не больше одной на view.**
- iOS/iPadOS: через SwiftUI `DisclosureGroup`.

### Color wells

Контрол выбора цвета текста/фигур; по тапу открывает color picker.

- Предпочитай **системный color picker** (знаком, хранит сохранённые цвета между приложениями).

## 6. Текст

### Labels

Статичный нередактируемый текст (можно копировать).

- Малый нередактируемый текст → label; малый редактируемый → text field; большой → text view.
- **Системные шрифты,** Dynamic Type по умолчанию; при кастомизации сохраняй читаемость.
- **Четыре системных цвета подписей** для иерархии важности:

| Цвет | Использование | iOS/iPadOS API |
|---|---|---|
| Label | основная информация | `label` |
| Secondary label | подзаголовок, дополнительный текст | `secondaryLabel` |
| Tertiary label | описание недоступного элемента/поведения | `tertiaryLabel` |
| Quaternary label | текст-водяной знак | `quaternaryLabel` |

- Полезный текст (ошибка, адрес, IP) делай **выделяемым**.

### Text fields

Прямоугольное поле для короткого конкретного текста (имя, email).

- Больше текста → text view.
- **Placeholder** («Email», «Password») + отдельная подпись над полем (placeholder исчезает при вводе).
- **Secure text field** для паролей и чувствительных данных.
- Размер поля ≈ ожидаемый объём текста.
- Несколько полей — **вертикальной стопкой**, равные промежутки, согласованные ширины.
- Логичный порядок перехода фокуса.
- **Валидация:** email — при уходе с поля; логин/пароль — до ухода с поля.
- Числа — через number formatter (десятичные, проценты, валюта; учитывай локаль).
- Переполнение: по умолчанию обрезка; можно перенос по символу/слову или многоточие в начале/середине/конце.
- **Показывай подходящий тип клавиатуры** (числа, URL…).
- **iOS/iPadOS:** **Clear button на trailing-конце.** Leading-край — изображение, объясняющее назначение поля; trailing — доп. функции (например, Bookmarks).

### Text views

Многострочный стилизованный текст, опционально редактируемый; скроллится при переполнении, по умолчанию выровнен по leading-краю, цвет — system label.

- Для длинного, редактируемого или специально форматированного текста; короткое → label / text field.
- Читаемость, **Dynamic Type**, проверка с Bold Text и др. accessibility-настройками.
- Полезный текст — выделяемый.
- Подходящий тип клавиатуры при редактировании.

## 7. Статус

### Progress indicators

Показывают, что приложение не зависло при загрузке или долгой операции; исчезают по завершении.

- **Determinate** (известная длительность): progress bar заполняется от leading к trailing; круговой — по часовой стрелке. **Indeterminate** (activity indicator / spinner): вращающаяся анимация.
- **По возможности — determinate;** переключай indeterminate → determinate, когда длительность стала известна.
- **Равномерный и честный прогресс:** **90%** за **5 секунд** и последние **10%** за **5 минут** — выглядит зависанием и обманом.
- Индикатор всегда в движении; при остановке процесса — объясни проблему.
- **Не переключай круговой стиль на bar** (разные формы — ломают раскладку).
- Описание — точное и короткое; избегай пустых «loading», «authenticating».
- **Постоянное место** для индикатора.
- Прерывание: **Cancel**, если нет побочных эффектов; при потере прогресса — ещё и **Pause**; предупреждай alert'ом, если отмена теряет прогресс.
- **Refresh control (iOS/iPadOS)** — спиннер, скрытый до pull-to-refresh: всё равно обновляй данные автоматически; заголовок — только ценный (время последнего обновления), не инструкция «потяните».
- Внутри кнопки для долгого действия — activity indicator (см. Buttons).

### Gauges

Числовое значение в диапазоне, по круговой или линейной траектории.

- **Standard** — индикатор в точке значения; **capacity** — заливка до значения. Вариант **accessory** — в стиле watchOS complications, для **iOS Lock Screen widgets**.
- Краткие подписи для текущего значения и **обоих концов** диапазона (их читает VoiceOver).
- Градиент по пути, если помогает смыслу (температура: красный → синий).
- *Для сравнения, macOS level indicator:* заливка по умолчанию **зелёная**; discrete-сегменты заливаются только целиком.

## 8. Не для iOS/iPadOS: Token fields, Rating indicators, Lockups

- **Token fields** — только macOS (в iOS используй **tokens в search field**). Текст превращается в token по **запятой** (можно добавить Return); подсказки по умолчанию появляются сразу — задержку можно увеличить; у token — context menu.
- **Rating indicators** — только macOS: ряд звёзд, дробных символов нет (значение округляется), интервалы фиксированы; кастомный символ вместо звезды — только если смысл очевиден.
- **Lockups** — только tvOS: **четыре** типа (cards, caption buttons, monograms, posters); при фокусе увеличиваются — оставляй место между ними, размеры в ряду одинаковые.
