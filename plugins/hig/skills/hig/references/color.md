# Цвет — значения и правила (Apple HIG, раздел Color)

Источник: developer.apple.com/design/human-interface-guidelines/color (обновление от 16.12.2025, значения системных цветов — от 9.06.2025, эпоха Liquid Glass).
Apple подчёркивает: значения даны для макетов; в коде используйте системные цвета через API (`Color.red`, `UIColor.systemRed`), они могут меняться от релиза к релизу. В HTML-прототипе — значения ниже как CSS-переменные.

## Правила

- Один цвет — одно значение. Если фирменный цвет помечает интерактивность (например, borderless-кнопки), не красьте им же неинтерактивный текст.
- Каждый цвет нужен в 4 вариантах: светлая тема, тёмная, светлая + Increase Contrast, тёмная + Increase Contrast. Даже если приложение только в одной теме — дайте светлый и тёмный вариант (нужно для адаптивности Liquid Glass).
- Не передавайте информацию только цветом: добавляйте форму, иконку или подпись. Особенно проблемные пары при дальтонизме — красный/зелёный и синий/оранжевый.
- Проверяйте контраст в обеих темах (см. ниже и accessibility-минимумы в SKILL.md).
- Не переопределяйте смысл семантических цветов: separator не делаем цветом текста, secondaryLabel — фоном.
- Учитывайте культурный контекст (красный — опасность не везде).
- Тестируйте при разном освещении: на ярком свету цвета темнеют и глохнут, в темноте — ярче и насыщеннее. True Tone сдвигает точку белого.
- Если пользователь выбирает цвет — используйте системный color picker.

### Liquid Glass и цвет
- По умолчанию стекло бесцветно — берёт цвет контента под ним. Тонировать можно, но **экономно**: только статусы и главное действие.
- Главное действие выделяйте цветом **фона** стеклянной кнопки, а не цветом её символа/текста (пример Apple: в тулбаре синим залит только «Done», остальные кнопки — нейтральные).
- Мелкие элементы (toolbar, tab bar) сами переключаются между светлым и тёмным видом под контент; символы и текст на них по умолчанию монохромные.
- На красочном фоне не делайте подписи контролов похожими по цвету — лучше монохром.
- Следите, чтобы в «состоянии покоя» (верх экрана до скролла) цветной контент не лежал под контролами похожего цвета.

### Управление цветом
- Встраивайте цветовой профиль в изображения; sRGB — безопасный вариант для большинства экранов.
- Display P3 (wide color) — для насыщенных фото/видео и значимых индикаторов; очень близкие P3-цвета на sRGB могут слиться, градиенты — обрезаться: при необходимости давайте отдельные варианты под sRGB.

Выводы:
- В светлой теме **ни один** стандартный цветной системный цвет, кроме Indigo (5.1), не проходит 4.5:1 на белом → мелкий цветной текст на белом делайте в варианте Increased contrast (все ≥ **4.5**), либо крупным/жирным (порог 3:1 — проходят Red, Blue, Pink, Brown, Purple, Indigo, Gray), либо не текстом, а заливкой кнопки.
- Белый текст на заливке Blue (#0088FF) = **3.5:1** — годится только для жирного/крупного лейбла кнопки (≥ 3:1). Для мелкого — затемняйте фон (например, `#1E6EF4` = 4.6:1 с белым).
- Жёлтый, оранжевый, зелёный, mint, teal, cyan на белом (1.5–2.3) — только как заливка/индикатор, не как текст.
- В тёмной теме все цветные системные цвета проходят 4.5:1 на чёрном.

## Семантические цвета iOS/iPadOS (назначение)

Фоны — два набора, у каждого primary / secondary / tertiary:
- **system**: `systemBackground` → `secondarySystemBackground` → `tertiarySystemBackground` — для обычных экранов.
- **grouped**: `systemGroupedBackground` → `secondarySystemGroupedBackground` → `tertiarySystemGroupedBackground` — для сгруппированных списков (как «Настройки»).
- Primary — фон всего экрана; secondary — группы внутри него; tertiary — группы внутри secondary.

Передний план:

| Роль | UIKit |
|---|---|
| Основной текст | `label` |
| Второстепенный текст | `secondaryLabel` |
| Третичный текст | `tertiaryLabel` |
| Четвертичный текст (водяные знаки, неактивное) | `quaternaryLabel` |
| Плейсхолдер в полях | `placeholderText` |
| Разделитель с просвечиванием | `separator` |
| Непрозрачный разделитель | `opaqueSeparator` |
| Текст-ссылка | `link` |
